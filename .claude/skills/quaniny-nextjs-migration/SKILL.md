# هجرة كوانيني لـ Next.js

**الاتجاه مقفول** (قرار صاحب الصيدلية، سبتمبر 2026). اللي لسه مفتوح هو التوقيت.

الخلفية الكاملة في [`quaniny-website`](../quaniny-website/SKILL.md) — قسم «القرار المعماري».

## إشارة البدء

> **15–20 منتج متصوّر وجاهز.**

قبل كده: **HTML**. الهجرة بتشتري تعقيد بلا عائد، لأن العائد كله في **صفحات منتجات مفهرسة** وهي مش موجودة لسه.

| الشغل | القرار |
|---|---|
| لاندنج بيدج واحدة | ✅ HTML — صفحة واحدة مش بتعمل بنية كتالوج |
| صفحة أو اتنين منتج | ✅ HTML برابط نظيف + `Product` schema |
| كتالوج بتصنيفات وبراندات | ⏸️ **Next.js** — ده سببها |

**القاعدة الحاكمة: متبنيش الكتالوج مرتين.** لو اتبنى كتالوج HTML وبعد شهور اتنقل، الشغل كله بيتعاد. فلحظة بناء الكتالوج هي لحظة الهجرة.

## 🔴 اللي لازم ينجو — راجع كل بند وحدك بعد الهجرة

الموقع ده فيه شغل سيو متراكم شهور. الهجرة بتكسره **بصمت** لو اتعملت من غير القايمة دي.

| # | اللي لازم يفضل | إزاي تتأكد |
|---|---|---|
| 1 | **كل رابط مفهرس بنفس شكله بالظبط** — `/insurance/globemed` · `/pharmacy/shibin-el-qanater` · `/delivery-areas` | قارن `sitemap.xml` القديم بالروابط الجديدة **واحد واحد**. أي رابط اتغير = ترتيب ضاع |
| 2 | **17 بلوك JSON-LD** — Organization · WebSite · Pharmacy ×2 · FAQPage · BreadcrumbList · Service | عُدّهم قبل وبعد. والـ `@id` لازم يفضل نفسه (`https://quaniny.com/#org`) عشان الربط بينهم يفضل شغال |
| 3 | **نص الـ FAQ الظاهر = نص الـ schema حرف بحرف** | سكربت المقارنة في skill `verify` |
| 4 | **66 منطقة** في `delivery-areas` **و**`areaServed` — متطابقين | عُدّهم في الاتنين |
| 5 | `<meta name="msvalidate.01">` في الصفحة الرئيسية | Bing بيعيد فحصه — لو ضاع، التحقق بيسقط |
| 6 | **`chrome()` قبل الرسم** → تبقى layout component | قِس CLS. المرجع **0.000** — أي رقم أعلى يبقى رجعنا لورا |
| 7 | **طبقة القياس بقاعدة صفر بيانات شخصية** | اختبار التسريب في skill `verify` |
| 8 | `cleanUrls` بدون `trailingSlash` | App Router بيعمل ده افتراضيًا — بس اتأكد إن `/delivery/` بيحوّل على `/delivery` |
| 9 | دوال `/api/*.mjs` زي ما هي | في Next.js بقت Route Handlers — **و`req.body` بيتفك تلقائيًا**، عكس دوال Vercel المستقلة. ده مصدر عطل مسجّل |
| 10 | شريط `.qbar` و`body padding` في CSS مش JS | قاعدة الـ CLS نفسها |

## الترتيب

**1. ثبّت الأول، انقل بعدين.** اعمل فرع، انقل الموقع **زي ما هو** من غير أي feature جديدة. الهجرة اللي بتضيف حاجات في نفس الوقت مبتتحققش — مش هتعرف العطل من الهجرة ولا من الإضافة.

**2. الصفحات الثابتة الأول** (`/`, `/branches`, `/ask`, `/insurance/*`, `/pharmacy/*`). دي نسخ ولصق مع تحويل الـ chrome لـ layout.

**3. بعدها المسارات التفاعلية** (`/delivery`, `/cart`, `/products`) — دي اللي فيها حالة وفورمات.

**4. آخر حاجة الكتالوج الجديد.** أول ما الهجرة تثبت وتتحقق، ابني صفحات المنتجات المفهرسة — دي كانت الهدف من الأول.

**5. قبل النشر:** شغّل skill `verify` كامل. **وبعد النشر:** أعد إرسال `sitemap.xml` في Search Console و Bing.

## قرارات محسومة — متفتحهاش تاني

- **مفيش Prisma ولا Drizzle** دلوقتي. Supabase هي PostgreSQL وعندها عميل — الـ ORM طبقة زيادة بلا سبب
- **مفيش TypeScript إجباري** كشرط للهجرة. ممكن يتضاف بعدين
- **مفيش إعادة تنظيم مجلدات** خارج اللي App Router بيفرضه — كل تغيير بنية بيهدد الروابط المفهرسة
- **الربط المباشر بـ SQLite بتاع الـ ERP مرفوض** — لو احتجنا مزامنة تبقى API/Sync. راجع `quaniny-system-map`

## علامة إن الهجرة فشلت

مش الـ build. الـ build هينجح.

**العلامة الحقيقية: صفحة كانت في نتايج البحث بقت 404، أو CLS رجع فوق صفر، أو عدد الـ schema قل.** دي التلاتة اللي بتتفقد بصمت وبتظهر بعد أسابيع لما الزيارات تقل.

اعمل القياس **قبل** الهجرة واحتفظ بالأرقام. من غير خط أساس مش هتعرف إنك كسرت حاجة.
